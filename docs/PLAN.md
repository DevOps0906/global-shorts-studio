# 글로벌쇼츠 스튜디오 통합 기획서

Nov 15, 2026 · @RichNomad

## 요약

글로벌쇼츠 스튜디오는 "무엇을 만들지 찾기(레이더)"와 "그걸 3분 안에 쇼츠로 만들기(스튜디오)"를 한 화면에서 이어주는 쇼츠 제작 SaaS다. 레이더가 레퍼런스 채널의 떡상 영상을 찾고, 스튜디오가 미호메이트 방식(캡컷형 편집 + GPT 분석)으로 제목·대본·자막·컷·목소리를 자동으로 입힌다.

- **핵심 흐름**: 떡상 소재 발견 → 영상형/대본형 선택 → 길이·언어(한국어/일본어) 선택 → AI 4단계 분석 → 제목 3안·대본 3안 중 선택 → 화면 꾸미기 12종 → 저장·캡컷 ZIP·내 채널 업로드.
- **차별화**: 미호메이트는 "원본 영상을 이미 가진 사람"부터 시작한다. 글로벌쇼츠 스튜디오는 소재 발굴부터 시작하고, 제작 결과의 조회수를 다시 레이더로 추적해 "어떤 소재·제목이 터졌는지" 학습 루프를 만든다.
- **수익 구조**: 월 구독(레이더 채널 수) + 크레딧(분석·TTS·번역 호출 수). 강의 번들 판매가 첫 매출 채널이다.
- **가장 큰 리스크**: 해외 영상 짜깁기는 저작권과 유튜브 수익화 정책(재사용 콘텐츠)에 걸릴 수 있다. 7장에서 제품 수준의 대응을 정리했다.
- **구현 근거**: 화면 상태·크레딧·서버 계약·RLS·정책 기준·비기능 요구는 13장에 모았다.
- **추천**: 스튜디오(편집) MVP를 먼저 내 채널에 쓰고, 레이더는 이미 기획된 스키마를 그대로 붙인다. 두 제품을 따로 팔지 말고 하나로 판다.

## 1. 강의(노션) 핵심 정리

구미호 특강(육아맘이 월 2000 버는 유튜브+스레드)의 주장은 "이미 검증된 해외 영상을 골라, 현지화된 제목·대본으로 다시 터뜨린다"로 요약된다. 제품은 이 원칙들을 기능으로 바꾼 것이다.

| 강의 원칙 | 근거(강의 내용) | 제품 기능으로 바꾼 형태 |
| --- | --- | --- |
| 떠던 영상은 또 뜬다 | 해외에서 검증된 영상을 소재로 쓴다 | 레이더: 떡상배율·조회수 필터로 소재 자동 발굴 |
| 한국과 미국의 알고리즘은 따로 작동 | 미국에서 터진 영상을 한국에 다시 내도 겹치지 않는다 | 레이더: "타겟 국가" 태그와 "국내 미등장 소재" 표시 |
| 같은 영상도 일본에서 더 터진다 | 강의 사례: 404만→711만, 20만→90만, 31만→168만회(한국→일본) | 스튜디오: 한국어/일본어 자동 번역, 일본 채널 동시 제작 |
| 영상형 vs 대본형 | 영상형 = 대본 없이도 이해되는 영상, 대본형 = 대본이 있어야 이해되는 영상 | 스튜디오 첫 화면의 유형 선택, 유형별 프롬프트 분리 |
| 컨셉별 제목+대본 3안 | 컨셉에 따라 대본을 3가지로 만드는 챗봇 | 제목 3안 + 대본 후보 3안 카드 선택 |
| 캡컷 + GPT = 쇼츠 자동 프로그램 | GPT가 분석·대본, 캡컷이 편집 | 웹 편집기 + 캡컷 ZIP 내보내기 |
| 강사는 한국 2개·일본 2개 채널 운영 | 멀티 채널·멀티 국가 운영 | 채널 연결 여러 개, 업로드 시 채널 선택 |
| 스레드 쇼핑(인스타와 다른 말투) | 인기 글 수천 개를 GPT에 학습시켜 말투를 복제 | 2차 확장: 같은 소재로 스레드·인스타 글 자동 생성 |

**강의가 소개한 다른 수익 모델**: 플레이리스트 채널, 영화·드라마 쇼츠 짜깁기, 네이버 클립. 모두 "소재 발굴 + 빠른 편집"이 병목이라, 레이더의 소스 플랫폼만 늘리면 같은 스튜디오로 대응된다.

**배경음악 메모**: 강의 예시 영상의 배경음악(디지털 서커스 테마)을 찾아 적용해 보기로 한 메모가 있다. 상업 음원은 저작권 대상이라 제품에는 유튜브 오디오 보관함·로열티 프리 음원만 넣는다.

## 2. 미호메이트 화면·기능 분석

미호메이트(mihomate.saacademy.co.kr)는 "원본 영상 하나 넣으면 제목·대본·자막·컷 편집까지" 해주는 웹앱이다. 사용자 공유 화면 30여 장을 근거로 화면 4개와 편집 기능 12종을 정리했다.

### 2-1. 화면 흐름

| 단계 | 화면 | 핵심 요소 |
| --- | --- | --- |
| 1 | 홈 | 로고 + 한 줄 설명, "어떤 쇼츠를 만들까요?" 유형 카드 2개(영상형: 장면의 재미를 살리고 싶어요 / 대본형: 이유와 이야기를 알려주고 싶어요), 내 작업 목록(최근 10개 보관, 유형·언어·시각·원본 파일명, 지우기) |
| 2 | 설정 | 유형 바꾸기, 길이(원본 길이 유지 / 짧게 10\~15초 / 보통 15\~25초 / 길게 25\~30초), 언어(한국어·일본어), 참고할 원본 댓글(선택), 영상 드롭존(화면 어디에나 끌어다 놓기) |
| 3 | 분석 진행 | 4단계 스테퍼(영상 확인 → 장면 분석 → 제목·대본 생성 → 편집 마무리), 세부 작업 로그와 소요 시간, 사용 모델 표시, "끝날 때까지 이 화면을 켜 두세요" 경고 배너, 취소·영상 다시 선택 |
| 4 | 편집 스튜디오 | 3단 레이아웃: 좌(9:16 미리보기·컷 진행바·저장/업로드), 중(화면 꾸미기 12종), 우(제목·대본 선택과 컷별 편집) |

### 2-2. 분석 단계 세부 로그(화면에 보인 순서)

1. 효과음 시점 분석
2. 영상 확인
3. 장면·틀·모자이크 프레임 추출 (4\~27초)
4. 장면 분석 → 장면 경계 정밀 분석
5. 영상 틀 분석 (기존 상하단 테두리 감지)
6. GPT 화면·음성 분석 준비 (5\~27초)
7. AI 대본 생성 / AI 응답 (약 26\~34초, 모델명 표시)
8. 밝은 전환 화면 제거 (편집 마무리 단계)

전체 약 1분 안팎이며, 긴 영상·일본어는 몇 분 걸릴 수 있다고 안내한다. 분석이 브라우저 탭에서 돌아가는 구조라 탭을 벗어나면 멈춘다(우리는 서버 작업 큐로 개선).

### 2-4. 제목·대본 패널

- 제목 후보 3개(2줄, 둘째 줄 강조색) + 추천 이유 한 줄, "다른 제목 더 보기"
- 고른 제목 고치기: 첫 줄 / 둘째 줄(강조색) 입력칸
- 대본: "5컷·16초", "목소리 5/5줄", 대본 후보 3개(1. AI 추천 + 다른 관점 2개). 후보를 바꿔도 고친 자막은 후보마다 남는다
- 전체 원본 소리 ON/OFF, 컷 카드: 컷 썸네일 + 자막 + "화면:" 장면 설명 + 원본 소리 ON + 목소리 선택 + 미리 듣기 + 확정 체크 + 순서 이동
- 장면·대본 재구성(컷 순서·제목·자막·TTS 재생성, 추가 API 비용 경고)

### 2-5. 내보내기·계정

- 영상 저장하기(MP4), 캡컷 ZIP 저장(원본·음성·자막·편집 프로젝트 묶음, 일부 스타일은 이미지 트랙으로 고정), 대본 복사, 자막 파일 받기
- 내 채널에 업로드(새 탭의 유튜브 업로드 화면으로 연결)
- 작업 자동 저장(고치면 3초 뒤 저장)
- 상단: 계정 이메일, 내 숙제(강의 과제 연동), 관리 페이지, 로그아웃, 고객문의, 설정(API 키 연결 상태 초록불), 마이페이지

**설계에서 배울 점.** ① 모든 결정을 AI가 먼저 하고 사람은 "고르기"만 한다(제목 3안·대본 3안·스타일 썸네일). ② 비용이 드는 버튼에는 항상 비용 안내를 붙인다. ③ 웹에서 못 하는 정밀 편집은 캡컷 ZIP으로 넘긴다.

## 3. 통합 제품 정의와 사용자 흐름

통합 제품은 "찾기 → 만들기 → 올리기 → 재기" 4단계를 한 화면 안에서 끝낸다. 미호메이트가 "만들기"만, 숏츠레이더가 "찾기·재기"만 하던 것을 잇는 것이 기획의 핵심이다.

### 3-1. 정보 구조(IA)

| 메뉴 | 역할 | 출처 |
| --- | --- | --- |
| 홈 | 유형 선택(영상형·대본형), 오늘의 떡상 소재 5개, 내 작업 | 미호메이트 홈 + 레이더 요약 |
| 레이더 | 저장 채널 추적, 떡상배율 필터, 예약 스캔·알림, "이 영상으로 만들기" | 숏츠레이더 |
| 저장 채널 | 레퍼런스 채널·그룹·타겟 국가 태그 | 숏츠레이더 |
| 스튜디오 | 설정 → 분석 → 편집(3단) → 내보내기 | 미호메이트 |
| 내 작업 | 최근 작업, 플랜별 보관 개수 | 미호메이트 |
| 성과 추적 (신규) | 내가 올린 영상의 조회수·떡상배율, 원본 대비 성과, 터진 제목 패턴 | 신규(레이더 엔진 재사용) |
| 설정 | API 키(OpenAI·Typecast), 유튜브 채널 연결, 알림 수단, 브랜드 프리셋 | 둘 다 |
| 관리자 | 가입 승인, 숙제(강의 과제) 확인, 크레딧 관리 | 둘 다 |

> 상단 메뉴의 정본은 11-1이다. 위 표는 기능 묶음이며 메뉴와 1:1이 아니다: 스튜디오는 "새 영상"(`/`)에서 들어가는 흐름, 내 작업은 마이페이지 탭, 성과 추적은 로드맵 3단계(9-2 학습 루프)에서 메뉴로 추가한다. MVP는 업로드 기록(`uploads`)만 쌓는다.

### 3-2. 핵심 사용자 흐름

1. **찾기**: 레이더 예약 스캔이 떡상 영상을 찾아 텔레그램으로 알린다. 알림의 링크를 누르면 해당 영상 카드가 열린다.
2. **고르기**: 카드에서 "영상형으로 만들기 / 대본형으로 만들기"를 누른다. AI가 영상 길이·말 비중을 보고 어느 유형이 맞는지 추천 배지를 붙인다.
3. **설정**: 길이·언어·참고 댓글을 고른다. 레이더에서 왔다면 원본 댓글 상위 20개가 자동으로 채워진다.
4. **원본 확보**: 원본 파일을 사용자가 올린다(다운로드 권한은 7장 참고). 권리 확인 체크박스를 통과해야 분석이 시작된다.
5. **분석**: 서버 작업 큐에서 4단계가 돌고, 탭을 닫아도 계속된다. 끝나면 알림을 보낸다.
6. **편집**: 제목 3안·대본 3안을 고르고, 화면 꾸미기 12종으로 다듬는다. 한국어판을 끝낸 뒤 "일본어판 만들기" 한 번으로 번역본을 복제한다.
7. **올리기**: MP4 저장, 캡컷 ZIP, 또는 연결된 유튜브 채널에 예약 업로드(제목·설명·해시태그 자동 입력).
8. **재기**: 올린 영상을 레이더가 자동으로 추적한다. 48시간 뒤 "원본 대비 성과"와 "터진 제목 패턴"을 보여주고, 이 데이터가 다음 제목 추천 프롬프트에 들어간다.

### 4-5. 레이더 (기존 기획 재사용)

저장 채널·그룹, 추적 필터 4종(구독자·조회수·시간·떡상배율), 예약 스캔, 이메일·텔레그램 알림은 「숏츠레이더 기획서」 그대로다. 통합에서 더하는 것은 세 가지다.

- 카드의 "영상형으로 만들기 / 대본형으로 만들기" 버튼(설정 화면으로 소재 정보·댓글 전달)
- "국내 미등장" 배지: 같은 영상의 한국어·일본어 재가공본이 아직 없다면 표시(제목 검색 기반 추정)
- "제작함" 상태: 이미 만든 소재는 회색 처리해 중복 제작 방지

**1차 구현(task-005, 원본 지표만).** YouTube Data API v3 서버 공용 키로 Next.js 서버가 스캔한다. 조회수·구독자·게시 경과(시간)만 표시·정렬·필터하고(정렬: 조회수·최신순·구독자순), "새 영상"은 처음 발견 후 24시간 이내다. 떡상배율 필터·칸, 채널 평균 조회, "국내 미등장"·"제작함", 예약 스캔·알림은 "준비 중"(비활성)이다(사유 7-2). 화면 하단에 YouTube 서비스 약관·Google 개인정보처리방침 링크를 둔다. 한도: 사용자 채널 50개, 채널 확인 하루 50회, 수동 스캔 10분 간격, 사용자 하루 1,000유닛·서비스 하루 8,000유닛(LA 자정 초기화).

### 4-6. 성과 추적 (`/performance`, 신규)

- 내 채널 업로드 영상을 레이더 추적 대상에 자동 등록
- 원본 vs 내 영상 조회수, 24·48·72시간 성장 곡선, 국가(한/일)별 비교
- 터진 영상의 제목 유형·스타일·길이 통계 → "내 채널에서 잘 되는 제목" 프롬프트 예시로 자동 반영

### 4-7. 비즈니스 규칙

1. 크레딧 차감: 분석 1회, TTS 1줄, 번역 1회, 재구성 1회를 각각 따로 센다. 비용이 드는 버튼에는 차감량을 버튼 옆에 표시한다.
2. 분석 실패 시 크레딧을 자동 환불한다. 검증에 실패해도 과금될 수 있는 외부 API(번역·재구성)는 미리 안내한다.
3. 편집 내용은 고친 뒤 3초가 지나면 자동 저장한다. 대본 후보를 바꿔도 사용자가 직접 고친 자막은 유지한다.
4. 원본 영상 파일은 작업 완료 7일 뒤 삭제하고, 편집 데이터(JSON)와 최종 렌더만 남긴다.
5. 변형도 점수가 기준에 못 미치면 "내 채널에 업로드" 전에 부족 항목을 보여주고 한 번 더 확인받는다(차단이 아닌 경고).

## 5. AI 파이프라인 상세

"캡컷 + GPT"를 제품으로 바꾸면, GPT는 "무엇을 말할지(제목·대본·컷 구성)"를 JSON으로 정하고, 편집 엔진은 그 JSON을 "어떻게 보여줄지(렌더)"로 바꾼다. 이 분리가 핵심이다. JSON이 곧 편집 상태이므로 자동 저장·되돌리기·번역 복제·캡컷 내보내기가 모두 같은 데이터에서 나온다.

### 5-1. 4단계 처리

| 단계 | 작업 | 기술 | 목표 시간 |
| --- | --- | --- | --- |
| 1. 영상 확인 | 코덱·길이·해상도 확인, 9:16 여부, 오디오 분리 | ffprobe, FFmpeg | 2초 |
| 2. 장면 분석 | 장면 경계 감지, 장면별 대표 프레임, 기존 상하단 틀·검은 여백 감지, 원본 로고·자막 위치(모자이크 후보), 효과음 시점(오디오 에너지 피크), 원본 음성 받아쓰기 | PySceneDetect, FFmpeg cropdetect, OCR, Whisper | 10\~30초 |
| 3. 제목·대본 생성 | 대표 프레임(최대 12장) + 받아쓴 말 + 참고 댓글 + 유형·길이·언어를 비전 LLM에 넣고 구조화 JSON 출력 | GPT/Claude 비전 모델, JSON Schema 강제 | 20\~40초 |
| 4. 편집 마무리 | 컷 경계 정리, 밝은 전환 화면 제거, 기본 템플릿·스타일 적용, 미리보기용 저화질 프록시 생성 | FFmpeg | 5\~10초 |

모든 단계는 서버 작업 큐에서 돌고, 각 세부 작업의 시작·종료를 `job_steps`에 기록해 화면 로그로 보여준다.

### 5-2. 유형별 프롬프트 설계

| 항목 | 영상형 | 대본형 |
| --- | --- | --- |
| 목표 | 장면의 웃음·공감·센스를 살리는 짧은 리액션 자막 | 상황·원리·배경을 풀어주는 내레이션 |
| 자막 길이 | 컷당 8\~14자, 구어체, 추임새(ㅋㅋ, ㄷㄷ) 허용 | 컷당 15\~30자, 사실 위주 |
| TTS | 기본 끄기, 원본 소리 유지 | 기본 켜기, 원본 소리 낮춤 |
| 제목 | 상황 대비·반전("A vs B", "\~했더니") | 호기심·이유("\~한 이유", "사실은") |

제목 3안은 각각 다른 훅 유형(대비·호기심·감정)으로 강제해 서로 겹치지 않게 한다. 성과 추적 데이터가 쌓이면 "이 채널에서 조회수가 높았던 제목 5개"를 few-shot 예시로 넣는다.

### 5-3. LLM 출력 스키마 (편집 상태의 원본)

```json
{
  "titles": [
    { "line1": "집사는 트리 꾸미고", "line2": "고양이는 집 구하고", "hook": "contrast", "reason": "두 집의 트리 아래를 대비" }
  ],
  "scripts": [
    {
      "label": "AI 추천",
      "cuts": [
        { "start": 0.0, "end": 3.2, "caption": "트리 밑, 막을까 내줄까?", "scene": "사람이 투명 매트를 펼친다", "tts": true, "keepOriginal": true, "zoom": 1.0 }
      ]
    }
  ],
  "sfx": [{ "at": 2.4, "type": "pop" }],
  "mosaic": [{ "from": 0, "to": 12.5, "box": [0.72, 0.04, 0.24, 0.06] }],
  "comments": [{ "cut": 7, "text": "트리 산 줄 알았는데 고양이 집 지음" }],
  "meta": { "description": "...", "hashtags": ["#shorts", "#고양이"] }
}
```

### 5-4. 목소리·번역·렌더

- **TTS**: Typecast를 기본 엔진으로 두고, 컷별로 생성해 바뀐 줄만 다시 만든다(변경 감지 해시). ElevenLabs는 일본어·영어 품질용 보조 엔진이다. 사용자 본인 API 키 연결(BYOK)을 지원해 우리 원가를 낮춘다.
- **번역**: 자막·제목을 직역하지 않고, "해당 국가 쇼츠 화법으로 다시 쓰기" 프롬프트를 따로 둔다(강의의 한→일 사례도 제목을 일본식 표현으로 바꿨다). 일본어 글꼴·줄바꿈 규칙을 별도 프리셋으로 적용한다.
- **미리보기와 최종 렌더를 같은 코드로**: Remotion(React) 컴포지션 하나로 브라우저 미리보기와 서버 렌더를 동시에 처리해 "보이는 대로 나온다"를 보장한다. 단순 조합은 FFmpeg 필터 체인으로 더 싸게 렌더한다.
- **캡컷 ZIP**: 원본·컷별 TTS·SRT·제목 PNG·템플릿 PNG·사용 안내를 묶는다. 캡컷 프로젝트 파일(draft) 형식은 비공식이라 캡컷 업데이트로 깨질 수 있다. MVP는 "에셋 + SRT + 가이드"로 시작하고 draft 자동 생성은 실험 기능으로 둔다.

### 6-3. 영상 1개당 원가 (추정)

원가는 LLM에 넣는 프레임 수와 TTS 줄 수가 좌우한다. 아래는 설계 목표치이며 MVP에서 실측해 보정한다.

| 항목 | 가정 | 목표 |
| --- | --- | --- |
| LLM 분석 | 프레임 12장 + 대본 3안 1회 | 건당 100원 이하 |
| TTS | 5\~7줄 | BYOK 시 0원, 자체 키 시 건당 100원 안팎 |
| 워커·렌더 | 30초 영상, CPU 1\~2분 | 건당 30원 이하 |
| 스토리지 | 원본 7일 후 삭제 | 무시 가능 |

오차를 크게 잡아도 건당 300원 안쪽이다. 월 100개를 만드는 사용자의 원가가 3만 원 안팎이라, 플랜 가격은 이 값의 2\~3배에서 시작한다(9장).

## 7. 저작권·정책 리스크와 대응

해외 영상 짜깁기는 이 제품의 가장 큰 매출 동력이자 가장 큰 리스크다. 사용자 채널이 수익화를 못 받거나 저작권 신고를 당하면 해지로 이어지므로, 정책 대응을 기능으로 넣는다. 아래는 법률 자문이 아니며, 출시 전 저작권 전문 변호사 검토를 권한다.

### 7-1. 유튜브 수익화 정책 2가지

| 정책 | 내용 | 제품에 주는 의미 |
| --- | --- | --- |
| 재사용 콘텐츠(Reused) | 다른 곳의 영상을 의미 있는 해설·실질적 변형·교육/오락 가치 없이 올리면 수익화 불가. 원 제작자의 허락이 있어도 적용된다는 해석이 있다 ([출처](https://www.lilachbullock.com/?p=188338)) | 자막만 얹은 번역본은 위험. 내레이션·해설·구성 변경이 필수 |
| 비진정성 콘텐츠(Inauthentic) | 2025년 7월 15일 "반복성 콘텐츠"에서 이름이 바뀌었고, 반복적·대량 생산 콘텐츠를 다룬다 ([출처](https://www.lilachbullock.com/?p=194003)). 채널 전체를 보고 판단한다 ([출처](https://air.io/en/youtube-hacks/reused-content-monetization-rejected)) | 같은 템플릿·같은 톤으로 찍어내면 채널 단위로 거절될 수 있다 |

정책은 자주 바뀐다. 분기마다 유튜브 공식 정책 페이지를 다시 확인하는 운영 일정을 둔다.

### 7-2. 저작권·약관 리스크

- **다운로드**: 유튜브 영상을 내려받는 기능은 유튜브 약관에 어긋난다. 제품에는 다운로더를 넣지 않고, 사용자가 권리를 가진 파일만 업로드하게 한다.
- **저작권**: 타인의 영상을 재가공해 올리는 것은 변형 정도와 무관하게 저작권 침해가 될 수 있다. Content ID 클레임과 저작권 경고(3회 시 채널 삭제)는 수익화 정책과 별개다.
- **YouTube API 데이터**: 개발자 정책 III.E.4.h에 따라 API 데이터로 새 지표(떡상배율·채널 평균 조회수 등)를 계산하지 않는다. 원본 값만 보여 주고, 저장한 API 데이터는 30일 안에 갱신하거나 지운다(`radar.purge_stale()`, pg_cron 매일). 떡상배율은 다른 근거가 확인될 때까지 보류한다.
- **음원**: 상업 음원은 넣지 않는다. 로열티 프리 라이브러리만 제공한다.
- **인물**: 어린이·일반인이 나오는 영상은 초상권 문제가 걸린다. 강의 사례 중 아이가 나오는 영상이 여럿 있어, 얼굴 모자이크 제안을 기본값으로 둔다.

### 7-3. 제품 수준의 대응

| 기능 | 설명 | 우선 |
| --- | --- | --- |
| 권리 확인 체크 | 업로드 시 권리 보유·라이선스 유형(직접 촬영/허락/라이선스/기타) 선택, 원본 출처 URL 기록 | Must |

**사업적 판단.** "해외 영상을 가져다 번역만 해서 올리는 도구"로 홍보하면 단기 매출은 나오지만 플랫폼 정책에 따라 고객이 한꺼번에 이탈할 수 있다. "인기 소재를 발굴하고, 내 해설·내 스타일로 빠르게 만드는 도구"로 포지셔닝하고, 변형도 점수를 핵심 차별점으로 내세우는 것을 권한다.

### 9-3. 추천안

## 10. 강의 커리큘럼 연계와 보강안

구미호 정규강의(5강)를 제품과 맞춰 보면, 3·4강은 이미 기획된 기능으로 대부분 덞인다. 1·2·5강은 제품에 없는 영역이다. 특히 스레드 쇼핑(2강)과 투트랙 수익화(5강)는 강의의 절반인데 도구가 없다. 이 두 개를 모듈로 추가하는 것이 핵심 보강이다.

### 10-1. 차시별 기능 매핑

| 차시 | 강의 내용 | 현재 제품 | 보강할 기능 |
| --- | --- | --- | --- |
| 1강 | OT 및 유튜브·스레드 계정 세팅 | 없음(설정에 API 키만) | **온보딩 체크리스트**: 유튜브 채널 연결(한국·일본 구분), 스레드 계정 연결, 채널 기본 설정 점검, 레퍼런스 채널 스타터 팩 자동 담기, 텔레그램 알림 연결 |
| 2강 | 스레드 쇼핑 비법 | 없음 | **스레드 쇼핑 스튜디오(신규 모듈)**: 10-2 참고 |
| 3강 | 유튜브 기획 및 해짜 프로그램 이해 | 레이더 + 스튜디오(영상형·대본형) | 영상형/대본형 자동 추천, 기획 메모(왜 이 소재인가) 저장 |

### 10-2. 신규 모듈 — 스레드 쇼핑 스튜디오

강의 노트의 핵심(인스타와 다른 스레드 말투, 인기 글 수천 개를 GPT에 학습시킨 방법, 후기 유도)을 그대로 기능으로 바꾼다.

| 기능 | 상세 | 우선 |

| 상품 입력 | 상품 링크·사진·한 줄 메모 → 상품 특징 자동 요약 | Must |
| 말투 엔진 | 인기 스레드 쇼핑 글 패턴(첫 줄 훅·사적인 경험담·짧은 줄바꿈)을 few-shot으로 넣어 글 3안 생성. 내 글 중 반응 좋았던 글을 예시로 자동 추가 | Must |
| 말투 비교 | 같은 상품을 스레드형·인스타형으로 나란히 보여주기 | Should |
| 쇼츠 연결 | 스튜디오에서 만든 쇼츠를 스레드 글에 붙이거나, 스레드 글에서 쇼츠 대본형 대본을 만들기 | Should |
| 광고 표시 자동 삽입 | 제휴 링크가 들어간 글에는 경제적 이해관계 표시 문구를 자동으로 넣는다(표시 누락 시 추천·보증 심사지침 위반 위험) | Must |
| 예약 게시·댓글 링크 | 스레드 예약 게시, 본문은 링크 없이 두고 첫 댓글에 링크 달기 옵션 | Should |
| 후기 수집 | 구매자 후기 요청 문구·선물 이벤트 템플릿 | Could |
| 큰 글씨 모드 | 강의 사례(68세 수강생)처럼 시니어 사용자를 위한 글자 크기 확대·단계별 안내 | Should |

### 10-3. 신규 모듈 — 투트랙 수익 대시보드

"소재 하나 → 쇼츠(광고 수익) + 스레드 글(제휴 수익)" 원소스 투트랙을 한 화면에서 관리한다.

- **수익 합계**: 유튜브 예상 수익(YouTube Analytics API, 채널 연결 시) + 제휴 수익(클릭·전환은 제휴사 리포트 수기 입력 또는 CSV 업로드로 시작)
- **소재별 수익**: 같은 레이더 소재에서 나온 콘츠·스레드 글을 묶어 "어느 소재가 돈이 됐는지" 표시
- **채널별·국가별**: 한국 채널 vs 일본 채널 수익 비교(4강 연계)
- **다음 할 일 추천**: "이 소재는 일본어판이 없어요", "이 쇼츠에 연결된 스레드 글이 없어요" 같은 수익 빈칸 알림

### 10-4. 강의에 없지만 추가하면 좋은 내용

| 보강 차시 | 내용 | 제품 연결 | 이유 |
| --- | --- | --- | --- |
| 3.5강 (또는 3강 안) | 저작권·수익화 정책 안전 운영 | 권리 확인, 변형도 점수, 반복성 경고 | 해짜 모델의 가장 큰 리스크. 수강생 채널이 수익화에서 거절되면 강의 후기가 무너진다 |
| 6강 | 성과 분석과 개선 루프 | 성과 추적, 터진 제목 패턴 | 첫 영상이 안 뜨는 수강생의 이탈을 막는다 |
| 7강 | 하루 30분 자동화 루틴 | 예약 스캔 → 텔레그램 알림 → 스튜디오 제작 → 예약 업로드·스레드 게시 | 강의 종료 후에도 매일 제품을 쓰게 해 구독 전환으로 잇는다 |

### 10-5. 숙제 연동 ("내 숙제" 메뉴)

미호메이트 상단의 "내 숙제"를 차시별 미션으로 구체화한다. 미션 완료는 제품 안 행동으로 자동 판정하고, 강사는 관리자 화면에서 수강생별 진도를 본다.

1. 1강: 유튜브·스레드 계정 연결, 레퍼런스 채널 30개 담기
2. 2강: 스레드 쇼핑 글 5개 예약 게시
3. 3강: 영상형 2개·대본형 1개 업로드(변형도 60점 이상)
4. 4강: 같은 소재로 일본어판 3개 업로드
5. 5강: 투트랙 수익 대시보드 연결, 소재 1개로 쇼츠+스레드 글 세트 만들기

**로드맵 반영**: 스레드 쇼핑 스튜디오는 2단계(유료 출시)에, 투트랙 수익 대시보드와 숙제 연동은 3단계(학습 루프)에 넣는다. 강의 번들을 팔 경우 숙제 연동은 MVP 바로 다음으로 당긴다. 강사 입장에서 가장 큰 구매 이유가 되기 때문이다.

### 11-3. 버튼 반응과 프로그레스 규칙

모든 버튼은 올리면 살짝 뜨고, 누르면 눌리며, 키보드 포커스 표시가 보여야 한다. 시간이 걸리는 작업은 반드시 진행률을 보여 준다.

| 상황 | 표시 | 기준 시간 | 끝났을 때 |
| --- | --- | --- | --- |
| 영상 분석 | 전체 % + 남은 시간 + 4단계 | 약 1분 | 편집 화면 열기 버튼 |
| 영상 렌더·ZIP·SRT·일본어판·음성 생성·업로드 | 작업명 + % 막대, 다른 버튼 잠금 | 3\~10초(샘플) | 완료 메시지 |
| 레이더 스캔 | "스캔 중…" + % 막대 | 3초 안팎 | 결과 새로 고침 + 토스트 |
| 채널 추가·충전·설정 저장·문의 접수·로그인 | 버튼 비활성 + % 막대 | 2\~4초 | 토스트 안내 |

진행률은 실제 서버 작업에서는 `job_steps`의 완료 단계 수로 계산하고, 화면은 2초마다 폴링한다. 막대는 줄무늬가 흐르는 애니메이션이며, 모션 줄이기 설정이면 멈춘다.

### 11-4. 반응형 글자 크기

## 12. 구현 계획 (GitHub: DevOps0906/global-shorts-studio)

레포 이름은 `global-shorts-studio`로 하고, 디자인 시안과 기획서를 먼저 넣은 뒤 4주 단위로 MVP를 만든다. 코드 안 스키마 이름은 기획대로 `radar`, `studio`를 쓴다.

### 12-1. 레포 구조

| 경로 | 내용 |
| --- | --- |
| `docs/PLAN.md` | 이 기획서(마크다운 사본) |

| `design/tokens.css` | 색·글자 크기·구간 변수 |

### 12-2. 기술 스택

| 영역 | 선택 | 이유 |
| --- | --- | --- |
| 앱 | Next.js(App Router) + TypeScript + Tailwind + shadcn/ui | 기존 스택과 같아 재사용이 쉽다 |
| 데이터·인증 | Supabase(PostgreSQL, Auth, Storage) | 구글 로그인, 역할(RBAC), 작업 상태 저장 |

| 편집 미리보기 | Remotion | JSON을 그대로 미리보기·렌더로 변환 |
| 수집 | YouTube Data API v3 | 쿼터 표(4장)대로 사용 |

### 12-3. 4주 마일스톤

9-2의 1단계(MVP)를 계정·운영 화면까지 포함해 4주 개발 일정으로 다시 짠 것이다. 결제(토스페이먼츠)·예약 업로드는 9-2의 2단계(유료 출시)에 남는다.

| 주 | 목표 | 완료 기준 |
| --- | --- | --- |
| 1 | 앱 뼈대, 디자인 토큰 적용, 로그인, 공통 메뉴 | 시안과 같은 상단 메뉴가 3구간 반응형으로 보인다 |
| 2 | 레이더·저장 채널(스냅샷 수집, 떡상배율 계산), 고객문의·설정 | 채널 20개로 하루 1회 스캔 결과가 나온다. 문의 접수와 설정 저장이 새로 고침 후에도 남는다 |
| 3 | 스튜디오 분석 4단계, 제목 3안·대본 3안 | 영상 1개가 1분 안팎에 편집 JSON까지 만들어진다 |
| 4 | 편집 화면, 캡컷 ZIP·SRT 저장, 크레딧·마이페이지, 관리 페이지(작업 큐·회원) | 수강생 3명이 처음부터 끝까지 영상 1개를 만든다. 운영자가 작업 재시도·크레딧 지급을 하고 감사 기록이 남는다 |

**작업별 위험도와 구현 워커** (위험·중요도·난이도 중 가장 높은 것, 낮음 haiku · 보통 sonnet · 높음 opus)

| 작업 | 위험도 | 이유 |
| --- | --- | --- |
| task-001 앱 생성·토큰 | 보통 | 의존성 다수, 이후 모든 화면의 기반 구조(중요도) |
| task-002 공통 메뉴·반응형 | 낮음 | 화면·스타일만 |
| task-003 Supabase·DB 적용 | 높음 | 마이그레이션·RLS·크레딧 |
| task-004 구글 로그인·역할 | 높음 | 인증·권한 |
| task-005 레이더 수집 | 높음 | YouTube API 외부 계약·쿼터 |
| task-006 스튜디오 분석 | 높음 | 워커·큐·LLM 외부 계약, 크레딧 차감 |
| task-007 편집·내보내기·크레딧 | 높음 | 크레딧·파일 처리, 여러 모듈(난이도) |
| task-008 고객문의 | 보통 | 상태·데이터가 붙는 화면(support_tickets, 본인 행 RLS 기존) |
| task-009 설정 | 보통 | 상태·데이터가 붙는 화면(user_settings), 큰 글씨 모드 연결 |

### 13-3. 크레딧 규칙

1크레딧 = 영상 1개 분석. 9장 플랜의 "월 N개"는 N크레딧이다.

| 행동 | 차감 | 비고 |
| --- | --- | --- |
| 분석(4단계) | 1 | 실패·취소(3단계 전) 시 환불 |
| 장면·대본 재구성 | 1 | 버튼 옆에 표시(4-7) |
| 일본어판 만들기(번역) | 1 | 제목·자막·TTS 번역 포함 |
| TTS 생성 | 영상당 첫 생성 0(분석에 포함), 이후 고친 줄 10줄마다 1 | 바뀐 줄만 다시 만든다(5-4) |
| 렌더·캡컷 ZIP·SRT | 0 | 원가가 낮아 무료 |

- 잔액 = `credit_ledger.delta` 합계. 차감·환불·지급은 DB 함수 하나로만 기록하고(잔액 확인과 기록을 한 트랜잭션), 클라이언트는 직접 쓰지 않는다.
- 모든 기록에 멱등 키(`job_id:행동:attempt_no`)를 둬 같은 요청이 두 번 와도 한 번만 차감한다. 재시도는 같은 작업의 `attempt_no`를 올리므로 다시 차감되고, 환불은 차수당 한 번만 허용한다.
- 동시 요청은 사용자 단위 잠금(advisory lock)으로 순서대로 처리해 잔액이 음수가 되지 않게 한다. 크레딧 함수는 service_role만 실행한다(사용자 요청은 Next 서버가 대신 호출).
- 작업 생성 시 먼저 차감하고, 실패하면 `reason=refund` 기록을 더한다(기존 행을 고치지 않는다).

### 13-6. 정책 감시 기준 (12-4 확정안)

**변형도 점수(0~100)**: 항목별 0~1로 계산해 가중치를 곱해 더한다. 60점 미만이면 업로드 전 경고(차단 아님, 4-7).

| 항목 | 가중치 | 1이 되는 기준 |
| --- | --- | --- |
| 새 내레이션 비중 | 30 | TTS·내 목소리가 영상 길이의 50% 이상 |
| 자막·해설 밀도 | 25 | 컷당 평균 12자 이상 |
| 컷 재배열·크롭 | 20 | 원본 순서와 다른 컷 30% 이상 또는 크롭·확대 적용 |
| 원본 소리 줄이기 | 15 | 원본 소리 사용 구간 50% 이하 |
| 추가 요소 | 10 | 댓글 반응·효과음·제목 중 2개 이상 |

- **반복 원본**: 같은 파일(SHA-256) 또는 같은 출처 URL을 한 사용자가 30일 안에 3번째 쓰면 `policy_flags.repeat_source` + 경고.
- **반복성**: 최근 10개 업로드 중 템플릿·목소리·제목 훅 유형이 모두 같은 영상이 7개 이상이면 "패턴 다양화" 제안.
- **권리 확인 누락**: 분석 자체를 막는다(Must). 우회 경로가 생기면 `policy_flags.no_rights`.
- 가중치와 기준은 수동 제작 10개(9-1)로 보정하고, 바꾸면 이 표만 고친다.

### 13-8. 보안·공급망

보안 레벨은 **L2**다(로그인, 결제 예정, 외부 OAuth 토큰·BYOK 키 보관).

- 비밀은 서버·워커 환경변수와 Vault에만. `.env.example`에는 이름만 둔다.
- 모든 테이블 RLS(13-5), 관리 행동은 전부 `admin_audit_log`.
